# VoxoL 0.1.5 release review

This release contains the current native application and inference improvements, built for Apple Silicon. The release was prepared in an isolated Git worktree; the installed 0.1.4 application is retained for the owner to test the update.

## Inference review

- Qwen correction results are scoped to a dictation UUID and the exact UTF-8 bytes of the system/user prompt plus output-token limit. Cached responses go through the final fidelity checks. Session replacement/end, Unicode differences, byte/entry bounds and late results are covered by unit tests.
- Parakeet caches exact audio windows and their feature-normalization mode. Decoding and vocabulary bias are rerun. Both encoder and Qwen caches are bounded and remain in memory.
- Cancelled Parakeet producers and Qwen generation tasks are joined. Core ML predictions already running finish normally. Incomplete token-limited Qwen responses are rejected.
- MLX reusable buffers default to a 64 MiB limit. This does not cap total application RAM or evict model weights.
- Speculative prompt lookup and experimental text-quality v3 switches remain disabled by default. Model weights and adapters are unchanged.
- Review found and fixed a final-recognition context bug: screen vocabulary now uses the captured context snapshot after the mutable session field has been cleared.

## Verification

- Original working project: 327 Swift tests, 3 skipped, zero failures; 56 Python tests passed.
- Isolated release source: 327 Swift tests, 3 skipped, zero failures; 5 inference-comparison Python tests passed. The private collection and unrelated research tooling were not included in this release snapshot.
- Repository policy, generated-source consistency, strict Swift formatting, signed arm64 Release build and French localization checks passed. All 807 extracted UI strings have French translations.
- Nine synthetic FR/EN runtime cases preserve the previous measured outputs. Two intentional timeout cases are followed by successful requests. Two other cases keep their pre-existing fidelity rejection; this suite is not a general quality score.
- Runtime dependencies match the versions in the preceding inference experiments, including MLX 0.31.6 and MLX Swift LM 2.31.3. Xcode's release build uses `-onlyUsePackageVersionsFromResolvedFile -disableAutomaticPackageResolution`.

## Release-binary real-time replay

A fresh 180-second recording replay on the release binary measured **9,557 ms** for the initial control, **2,639 ms** with anticipation, and **10,540 ms** for the fresh control after clearing session caches. ASR and final text were identical across all three passes, with no processing failure. Binary SHA-256: `08f42b5c83bf47550d5757c9a631dea7465f4e9d39f4207db995b2b85f4111a2`.

These measurements end at text ready, before insertion. They use one existing recording and warmed models on a MacBook Pro M4 with 16 GB RAM. Earlier runs of that recording measured 1.5–1.6 seconds after stopping; those values are not a guaranteed latency. This is a same-input latency comparison, not an independent quality ranking against other products. Audio and full transcripts remain local.

## Distribution

The DMG contains `VoxoL.app` at its root and an Applications shortcut. Bundle identity is `com.voxol.VoxoL`, version `0.1.5`, build `5`, arm64. The Apple Development signature uses team `L4452G7VZN`, matching the existing 0.1.4 updater's trust check. This build is not notarized; no Developer ID signing identity is available on the release machine.

The update feed is the GitHub release list. A stable published `v0.1.5` release with a `.dmg` asset is discoverable from 0.1.4. The release checks validate the mounted image and feed without invoking application replacement. Physical microphone capture and installation/relaunch remain the owner's end-to-end test.
